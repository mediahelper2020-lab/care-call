# AI 안심돌봄

독거노인 등 돌봄이 필요한 대상자에게 AI가 정기적으로 안부전화를 걸고, 대화 내용을 분석해 이상 징후를
담당 사회복지사와 보호자에게 알리는 웹 기반 돌봄 모니터링 서비스입니다.

**이 서비스는 AI가 긴급상황을 단독으로 확정하지 않습니다.** 위험 신호가 감지되면 담당자에게 즉시 확인을
요청하는 Human-in-the-loop 방식으로 동작하며, 실제 119 자동신고 기능은 포함하지 않습니다.

## 1단계 MVP 범위

대상자 등록 → 가상 안부전화 → AI 분석 → 위험도 분류 → 대시보드 반영 → 담당자 확인 → 후속조치 기록까지
하나의 사용자 흐름으로 동작합니다.

## 실행

```bash
npm install
cp .env.example .env.local   # 값은 비워둬도 시연 가능
npm run dev                  # http://localhost:3000
```

외부 API 키가 없어도 전체 흐름이 그대로 동작합니다. LLM은 규칙·휴리스틱 기반 분석기로, 전화는 가상 통화
시뮬레이션으로 대체됩니다. 초기 데이터로 대상자 124명과 최근 30일 통화 이력이 준비되어 있습니다.

## 화면

| 경로 | 설명 |
| --- | --- |
| `/` | 대시보드. 오늘의 KPI, 우선 확인 대상자, 안부전화 시뮬레이션, 대상자 목록 |
| `/clients` | 대상자 관리. 상태별 필터, 일정·동의 현황 |
| `/clients/new` | 대상자 등록 |
| `/clients/[id]` | 대상자 상세. AI 요약·분석, 후속조치 기록, 변화 추이, 통화 이력 |
| `/notifications` | 위험 신호 알림 |
| `/privacy` | 개인정보 보호 조치, 보유기간 관리, 관리자 활동 로그 |

## 위험도 분류

규칙 기반 탐지와 AI 문맥 분석을 함께 쓰는 하이브리드 구조입니다. 규칙이 잡은 긴급 신호는 AI 판단과
무관하게 항상 유지됩니다.

| 표시 | 기준 |
| --- | --- |
| `정상` | 특별한 위험 신호 없음 |
| `확인 필요` | 식사 곤란, 지속적 통증, 복약 어려움, 평소와 다른 생활상태, 반복적 무응답, 도움 요청 |
| `긴급 확인` | 낙상, 심각한 신체 이상, 즉각적인 도움이 필요하다는 취지의 발언 |

`긴급 확인` 판정 시에도 "긴급 확인이 필요한 신호가 감지되었습니다."라고만 표시하며, 모든 AI 분석 결과에는
"AI 분석 결과는 참고정보이며 최종 판단은 담당자가 확인합니다."를 함께 노출합니다.

## 교체 가능한 모듈

세 모듈 모두 인터페이스만 구현하면 서비스 코드를 바꾸지 않고 교체할 수 있습니다.

| 모듈 | 인터페이스 | 기본 구현 | 교체 방법 |
| --- | --- | --- | --- |
| LLM | `src/lib/ai/types.ts` `LlmProvider` | 규칙·휴리스틱 | `CARE_LLM_PROVIDER=anthropic` + `ANTHROPIC_API_KEY` |
| 전화 | `src/lib/telephony/types.ts` `CallProvider` | 가상 통화 시뮬레이션 | `CARE_CALL_PROVIDER` (2단계에서 Voice API 제공자 추가) |
| 저장소 | `src/lib/store/types.ts` `DataStore` | 메모리 | Supabase 구현 추가 (`supabase/schema.sql` 참고) |

## 개인정보 보호

- 안부 확인에 필요한 최소 정보만 수집합니다.
- 이름·연락처·통화 전문은 AES-256-GCM으로 암호화해 보관합니다 (`CARE_ENCRYPTION_KEY`).
- 관리자와 담당 사회복지사만 대상자 정보를 열람할 수 있고, 통화 원문은 그보다 더 좁게 제한합니다.
- 대시보드와 목록 화면에서는 이름을 마스킹합니다.
- 개인정보 처리 동의가 확인되지 않은 대상자에게는 안부전화를 진행하지 않습니다.
- 보유기간(`CARE_RETENTION_DAYS`)이 지난 개인정보는 통화기록과 함께 삭제합니다.
- 대상자 등록, 통화 실행, 후속조치 기록 등 주요 활동을 감사 로그로 남깁니다.

실제 배포 전에는 개인정보 보호 및 관련 법적 요건을 별도로 검토해야 합니다. `CARE_ENCRYPTION_KEY`가
설정되지 않으면 개발 전용 키로 동작하며, 이 상태로 실제 개인정보를 입력해서는 안 됩니다.

## 기술 구조

Next.js(App Router) + React + Tailwind CSS. 조회는 Server Component, 변경은 Server Action으로 처리합니다.
Vercel 배포와 Supabase 연동을 전제로 설계했습니다.

```
src/
  app/            화면과 Server Action
  components/     UI 컴포넌트
  lib/
    ai/           LLM 제공자, 대화 생성, 기본 분석기
    risk/         규칙 기반 탐지, 하이브리드 분석
    telephony/    전화 제공자, 시연 시나리오
    store/        저장소 인터페이스와 메모리 구현, 시드 데이터
    services/     대시보드·추이·통화 실행 서비스
```
